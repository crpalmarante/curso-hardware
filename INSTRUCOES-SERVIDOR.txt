============================================================
 COMO SUBIR O CURSO NO SEU SERVIDOR (nginx em 177.190.69.20)
============================================================

Dados do servidor:
  IP público fixo: 177.190.69.20
  Domínio próprio: palmarante.com.br
  Subdomínio do curso: curso.palmarante.com.br  (DNS pendente de criação)
  Acesso final:    http://curso.palmarante.com.br
  Acesso temporário (sem DNS): http://177.190.69.20/  (já funciona hoje)

Resumo do que vamos fazer:
  1) Apontar o subdomínio curso.palmarante.com.br para o IP do servidor (DNS).
  2) Enviar os arquivos do curso para o servidor.
  3) Instalar o servidor Python como serviço (roda sozinho, mesmo
     depois de fechar o terminal) na porta 8081 (interna).
  4) Configurar o nginx para publicar o curso na porta 80.
  5) (Opcional) Colocar HTTPS com certificado gratuito.

------------------------------------------------------------
 1) APONTAR O SUBDOMÍNIO PARA O SEU SERVIDOR (DNS)
------------------------------------------------------------
O domínio principal (palmarante.com.br) já é usado pelo Odoo e pela
loja — o curso fica no SUBDOMÍNIO curso.palmarante.com.br.
No painel de DNS do seu provedor de domínio, crie o registro:

  Tipo  Nome    Valor          TTL
  A     curso   177.190.69.20  300

Confira depois de alguns minutos (pode demorar até 24h):
  (no seu computador)  nslookup curso.palmarante.com.br
  (deve mostrar o IP 177.190.69.20)

Enquanto o DNS não propaga, o curso JÁ fica acessível pelo IP direto
(sem porta):  http://177.190.69.20/

------------------------------------------------------------
 2) ENVIAR OS ARQUIVOS PARA O SERVIDOR
------------------------------------------------------------
Do seu computador, na pasta do curso, rode:

    scp -r /home/palmarante/curso-hardware usuario@177.190.69.20:/var/www/

(Substitua "usuario" pelo seu usuário no servidor.)
Depois, entre no servidor:

    ssh usuario@177.190.69.20

------------------------------------------------------------
 3) CRIAR O SERVIÇO (roda sozinho para sempre)
------------------------------------------------------------
No servidor, crie o serviço:

    sudo nano /etc/systemd/system/curso-hardware.service

Cole este conteúdo (ajuste o caminho se precisar):

    [Unit]
    Description=Servidor do Curso de Informatica
    After=network.target

    [Service]
    WorkingDirectory=/var/www/curso-hardware
    ExecStart=/usr/bin/python3 /var/www/curso-hardware/servidor.py 8081
    Restart=always
    User=www-data

    [Install]
    WantedBy=multi-user.target

Salve (Ctrl+O, Enter, Ctrl+X) e ative:

    sudo systemctl daemon-reload
    sudo systemctl enable curso-hardware
    sudo systemctl start curso-hardware

Confira se está no ar:

    sudo systemctl status curso-hardware
    curl http://localhost:8081/

Dica: para ver os erros, use:  journalctl -u curso-hardware -f

IMPORTANTE: o serviço roda SEM a flag --publico (escuta só em
127.0.0.1:8081) — quem expõe na porta 80 é o nginx (passo 4).
A porta 8081 NÃO precisa estar aberta no firewall externo.

------------------------------------------------------------
 4) CONFIGURAR O NGINX (publica na porta 80)
------------------------------------------------------------
Crie a configuração:

    sudo nano /etc/nginx/sites-available/curso

Cole:

    server {
        listen 80;
        listen [::]:80;
        server_name curso.palmarante.com.br;

        client_max_body_size 20M;

        location / {
            proxy_pass http://127.0.0.1:8081;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        }
    }

Ative e recarregue:

    sudo ln -s /etc/nginx/sites-available/curso /etc/nginx/sites-enabled/curso
    sudo nginx -t          # tem que dizer "syntax is ok"
    sudo systemctl reload nginx

Esse bloco também atende o acesso direto pelo IP (http://177.190.69.20/),
pois é o primeiro server block de listen 80 do nginx (server padrão) —
útil enquanto o DNS do subdomínio não existe.

Pronto! Acesse no navegador:

    http://curso.palmarante.com.br   (após o DNS)
    http://177.190.69.20/            (temporário, sem DNS — funciona hoje)

Para o registro de alunos (com senha):
    http://curso.palmarante.com.br/alunos.html

------------------------------------------------------------
  BANCO DE DADOS (SQLite)
------------------------------------------------------------
Os dados ficam em:  /var/www/curso-hardware/dados/curso.db

Contém alunos, notas, presenças, atividades, o andamento
(módulos/aulas) de cada aluno, o caderno de exercícios e o
quiz dos apêndices (respostas objetivas e dissertativas).
Para backup, basta
copiar esse arquivo (com o serviço parado):

    sudo systemctl stop curso-hardware
    sudo cp /var/www/curso-hardware/dados/curso.db ~/backup-curso.db
    sudo systemctl start curso-hardware

Na primeira execução, o arquivo alunos.json antigo é importado
automaticamente (e renomeado para alunos.json.migrado).

------------------------------------------------------------
 5) (OPCIONAL) HTTPS COM CERTIFICADO GRÁTIS (Let's Encrypt)
------------------------------------------------------------
Com o certificado, o acesso vira https://palmarante.com.br
(cadeado de segurança no navegador). Rode no servidor:

    sudo apt install certbot python3-certbot-nginx
    sudo certbot --nginx -d palmarante.com.br -d www.palmarante.com.br

Siga o assistente (informe seu e-mail, aceite os termos e escolha
"redirect" para obrigar o HTTPS). O certbot configura e renova o
certificado sozinho. Para conferir a renovação:

    sudo certbot renew --dry-run

------------------------------------------------------------
 ATUALIZAR O CURSO (deploy incremental)
------------------------------------------------------------
Quando o código mudar (novos recursos, correções), atualize o
servidor SEM mexer no banco de produção. Da pasta do projeto:

    ./deploy-producao.sh usuario@177.190.69.20

O script faz automaticamente:
  1) Roda o teste de permissões local (cancela se falhar).
  2) Gera o pacote deploy-curso.tar.gz (arquivos versionados,
     SEM a pasta dados/ — o banco e as senhas do servidor ficam
     intactos).
  3) Faz backup do banco em ~/backup-<data>.db no servidor.
  4) Envia o pacote e extrai por cima em /var/www/curso-hardware.
  5) Reinicia o serviço curso-hardware e confere a API.

Se preferir manual, os arquivos que mudam são enviados por scp:

    scp servidor.py secretaria.html login-secretaria.html \
        alunos.html plano-de-aulas.html index.html \
        apendice-exercicios.html setup.py \
        usuario@177.190.69.20:/var/www/curso-hardware/
    ssh usuario@177.190.69.20 "sudo systemctl restart curso-hardware"

NUNCA envie a pasta dados/ (banco, senhas, segredo) — ela é
criada no servidor e não deve ser sobrescrita pelo seu computador.

 SENHA DO INSTRUTOR E DA SECRETARIA
------------------------------------------------------------
Senha padrão do instrutor:  instrutor123
Senha padrão da secretaria: secretario123

>>> TROCAR AS SENHAS EM PRODUÇÃO (forma correta) <<<

O serviço lê as senhas uma única vez, na inicialização, e o setup cria
os arquivos com dono = usuário que o executa. Por isso, em produção,
rode o setup COMO www-data e REINICIE o serviço em seguida:

    cd /var/www/curso-hardware

    # 1) Gera senhas fortes e grava os arquivos como www-data:
    sudo -u www-data python3 setup.py --gerar

    # 2) O setup mostra as senhas geradas na tela — ANOTE-AS.
    #    (Para senhas escolhidas por você: sudo -u www-data python3 setup.py
    #    responde interativamente, ou use --senha/--senha-secretario.)

    # 3) Reinicia para as novas senhas valerem (lidas só no start):
    sudo systemctl restart curso-hardware

    # 4) Confere (opcional):
    curl -s -X POST http://localhost:8081/api/login \
      -H 'Content-Type: application/json' -d '{"senha":"SUA_SENHA"}'
    # -> {"status":"ok"} ; com senha errada -> {"erro": "Senha incorreta"}

Se o setup rodar como outro usuário (ex.: seu usuário SSH), os arquivos
ficam 600 com dono errado e o serviço (www-data) não consegue ler —
corrija com:  sudo chown www-data:www-data /var/www/curso-hardware/dados/*.txt

------------------------------------------------------------
 APÊNDICES (DISKPART/GPARTED) E RESUMO DE EXERCÍCIOS
------------------------------------------------------------
Dois apêndices extras de armazenamento (disco novo) foram adicionados ao
curso: Apêndice A (Windows/Diskpart) e Apêndice B (Linux/GParted/Fdisk),
com quiz interativo de fixação em apendice-exercicios.html (link
"📝 Apêndices" no curso e "📝 Exercícios dos apêndices" no livro).

- Cada apêndice tem objetivas corrigidas na hora + 1 dissertativa
  (A = 9 + 1 questões; B = 11 + 1). Quando o aluno está identificado
  (?aluno=Nome), as respostas são sincronizadas com o servidor via
  /api/exercicios com aula_id no formato "AP|Apêndice A — ...".
- Os apêndices também entram no Plano de Aulas como aulas extras de
  armazenamento.

NO BANCO: as respostas ficam na MESMA tabela exercicios (aula_id
começando com "AP|") — NÃO precisa migração nem nenhuma ação no
deploy. O resumo do GET /api/exercicios separa os apêndices do caderno:

  nota_sugerida           -> objetivas só do CADERNO (aulas não-AP)
  ap_objetivas / ap_certas / ap_nota_sugerida -> objetivas dos apêndices
  disc_media              -> dissertativas avaliadas do caderno
  ap_disc_avaliadas / ap_disc_media -> dissertativas avaliadas dos apêndices
  aproveitamento          -> global (caderno + apêndices)

Todos esses valores entram como componentes próprios na "nota sugerida
de Exercícios" (a aba 📝 Exercícios do instrutor mostra, no detalhe,
"caderno X + dissertativas Y + apêndices disc Z · obj W + checkouts + provas").

ONDE APARECE EM PRODUÇÃO:
- Aba 📝 Exercícios do instrutor: objetivas e dissertativas dos apêndices
  e avaliação das dissertativas (nota 0–10). AVALIAÇÃO É SÓ DO INSTRUTOR:
  a secretaria apenas consulta (POST /api/dissertativa retorna 403 para
  o papel secretaria).
- Boletim impresso (🖨️ Boletim): seção "Apêndices — exercícios extras"
  com as objetivas (certas/total) e a nota de cada dissertativa
  ("Nota: X" ou "Entregue — aguardando nota").
- Selo âmbar "📝 N p/ avaliar" ao lado do nome quando há dissertativa de
  apêndice sem nota + filtro "📝 Com pendências" nas listas (combina com
  o "🔒 Só travados"). O selo some assim que o instrutor avalia.

Para conferir se um aluno respondeu o quiz dos apêndices, rode:
  curl -s 'http://localhost:8081/api/exercicios?aluno=NOME'
(o resumo trará os campos ap_* acima quando houver respostas de apêndice).

------------------------------------------------------------
 ACESSO TEMPORÁRIO / SOLUÇÃO DE PROBLEMAS DE REDE
------------------------------------------------------------
- Enquanto o DNS do subdomínio não existe, o curso abre por:
    http://177.190.69.20/            (porta 80 via nginx — sem porta no navegador)
  NÃO tente http://177.190.69.20:8081: o FIREWALL DO PROVEDOR de
  hospedagem bloqueia portas altas (8081 e até a 8080 da loja) de fora —
  só 80/443/8443 passam. A 8081 é interna (127.0.0.1), usada só pelo nginx.
- Para liberar portas altas é preciso abrir no painel do provedor
  (firewall em nuvem), não no servidor (ufw/iptables estão sem regras).

------------------------------------------------------------
 CAMINHO MAIS SIMPLES (sem nginx, caso um dia queira)
------------------------------------------------------------

    cd /var/www/curso-hardware
    python3 servidor.py 8081 --publico

Aí o acesso fica: http://curso.palmarante.com.br:8081 (ou IP:8081, se o
provedor liberar a porta).

------------------------------------------------------------
 SOLUÇÃO DE PROBLEMAS
------------------------------------------------------------
- "Erro de permissão": ajuste o dono da pasta:
    sudo chown -R www-data:www-data /var/www/curso-hardware
- A página abriu mas o registro de alunos não conecta:
    confira o passo 3 (nginx -t) e o serviço (curl http://localhost:8081/).
- Senha não funciona após o setup: lembre de reiniciar o serviço e de
  conferir o dono dos arquivos (www-data) — veja a seção de senhas acima.
- Para testar tudo sem mexer no servidor real:
    python3 servidor.py 8124   (abre em http://localhost:8124)
